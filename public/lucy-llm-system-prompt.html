System prompts on Lucy's local LLM

LM Studio 0.4.16 · Qwen3.6‑35B‑A3B · a read/edit guide for when you're at the machine

"The system prompt" on a local model is actually three layers stacked on top of each other. Only one of them is the box you type in — the other two explain the weird stuff (why it ignores you, why it always starts thinking). Here's all three.

What a system prompt even is: not a config file, not magic. The model eats one long list of messages, each tagged with a role — system, user, assistant. The system message is just the first one, and by convention it's where the persona / rules go. Qwen wraps it in "ChatML" fence tokens before feeding it in:

<|im_start|>system
You are a terse coding assistant.<|im_end|>
<|im_start|>user
hey<|im_end|>
<|im_start|>assistant

LM Studio re‑prepends your system text on every turn automatically — that's why it "sticks" through the whole chat.

1 Your system prompt the one you edit

This is the one you mean 95% of the time. On Lucy, in LM Studio:

  1. Open the Chat tab (💬, left rail).
  2. Look at the right‑hand sidebar — the "System Prompt" field is right at the top of the settings panel. That text box is your system prompt.
  3. Type/edit it there. It applies to the next message immediately.

To stop retyping it every session, save the whole config as a Preset (dropdown at the top of the chat) and reload it later.

2 The baked‑in chat template explains the thinking

The ChatML structure above lives inside the GGUF model file — that's the "chat template." One quirk it forces on this model:

It auto‑opens a <think> block at the start of every reply. Qwen3.6 is a reasoning model — the thinking is template‑level, not something in your system prompt. Toggle enable_thinking off in the load settings to suppress it: faster, but weaker on hard problems.

To actually see or override the template: My Models tab → gear on the Qwen model → Prompt Template / Jinja override. Leave it alone unless you have a reason — a wrong template breaks output entirely.

3 The hidden tool‑calling preamble the gotcha

When tool‑calling is ON, LM Studio silently injects a big # Tools — You have access to the following functions… block ahead of your own system message. So if you set a system prompt and the model seems to ignore it — that's usually why. It's not ignoring you; your text is just buried under the tools preamble. Turn tools off and your system prompt regains its punch.

4 See exactly what's being sent

Best way to demystify all three layers at once: LM Studio's Developer / verbose logging (Developer tab, or the app logs). Turn it on and it prints the fully‑rendered prompt sent to the model each turn — your system text, the ChatML fences, and any tools preamble, all assembled. Great for learning what's really going on under the hood.

5 The API route (no GUI)

Since you code: if you flip on LM Studio's local server (Developer tab → start server, OpenAI‑compatible), the system prompt is just the first element of the messages array — same concept, per request, driveable from any machine pointed at Lucy:

{
  "model": "qwen/qwen3.6-35b-a3b",
  "messages": [
    { "role": "system", "content": "You are terse." },
    { "role": "user",   "content": "hey" }
  ]
}

Default endpoint is http://<lucy-ip>:1234/v1/chat/completions.
